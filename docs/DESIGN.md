# 设计取舍

## 保留独立经历与信息边界

每个 Agent 的对话和已接触材料持续到 reset。同一个参与者再次接到问题时可以使用此前经历；创建新参与者则建立新的信息起点。Broker 通过公开问答组织协作，无法读取其他参与者的私有会话或底层材料。

这种设计能够明确表达“谁接触过什么”，代价是协调者需要更多沟通，多个参与者也可能重复工作。它没有自动保证独立判断更准确或协作更便宜。

## 围绕问题形成协作

运行环境提供创建、复用、跨组参与和继续提问的能力，不要求在入口预先定义完整任务图。每个问题保留独立的回答责任；子问题完成不自动证明总问题完成。

这增加了模型组织任务的自由，也增加了请求量和失控扩展的可能。当前原型提供问题级世界操作预算、单次活动轮数与到达事件上限，还没有成熟的成本优化调度策略。

## 让回答依据影响后续执行

来源依赖具有运行后果：某个回答依赖的观察位置新增材料时，该问题可以重新进入待判断状态。旧答案不可变；新判断通过追加答案或私下保留表达。

模型决定依据选择与结论内容。宿主检查来源身份和可用性、维护依赖关系，但不裁决开放语义的充分性。因此，当模型错误保留答案时，机械流程仍可能正确执行。失败分析见[答案复查案例](cases/answer-refresh.md)。

## 固定工具结构，动态校验资格

如果每次材料、余额或问题变化都重写工具参数枚举，请求前缀也随之变化。当前实现保持 schema 稳定，把动态资格检查放到宿主执行层。

这为缓存复用创造条件，同时要求错误信息清楚地告诉模型哪项前置条件未满足。非法提案不会因为工具出现在 schema 中就获得执行资格。真实记录见[缓存案例](cases/cache-continuity.md)。

## 增量交付仍保留连续历史

已投影的文本节点、引用和依据节点在后续输入中去重；当前责任、额度等易变小状态仍表达最新值。去重针对后续处境投影，不抹除一次主动重复读取取得的真实工具结果。

完整历史仍会增长。该机制不是语义压缩，也没有解决长期上下文上限和持久恢复。

## 研究问题

本项目关注：当参与者只能接触局部信息、持续保留经历并响应后来的反馈时，哪些协作和信息结构有助于解决问题？

当前证据主要支持局部机制与工程行为。更大规模协作收益需要同信息、同预算的强基线与更丰富任务验证。工具语言演化、编译和下一轮先验重构属于研究设想，尚未实现。
